# Known release-candidate limitations

November 9, 2026. This is a hackathon prototype under release review, not production-certified software.

- **FAILED reliability gate:** the original organizer event disappearance is unexplained. Namespace confusion and UI read-state defects were reproducible; actual committed-data deletion was not. Later native inspection found organizer.events empty and main absent. No incident-time evidence identifies deletion, eviction or another partition. No data was restored. Preserve the original MacBook context; see PERSISTENCE_AUDIT.md and PERSISTENCE_RECOVERY.md.
- **Physical acceptance NOT RUN for this candidate:** MacBook camera, Pixel 8, iPhone, Safari installed-app storage, camera permission/recovery, lighting, screenshot recompression, sustained scanning and radio-off handoffs need actual evidence. Desktop WebKit is not iOS hardware proof. The owner’s earlier Phase 1 physical observation does not certify this build.
- Private organizer/scanner keys remain non-exportable on their original browser/device. Records exports do not restore authority. Browser deletion/eviction, OS loss or compromised same-origin code can destroy/use keys. Persistence requests do not guarantee retention. Lost organizer authority can require a new event and ticket reissuance; no insecure backup was added.
- Independent full-fingerprint comparison and organizer approval remain necessary and cumbersome. Initial signed event packages are manually transferred; no shortened fingerprint or unauthenticated pairing bypass. Revocations are not immediate on disconnected devices. Distribute current packages/policies before a shift and after changes.
- Simultaneous duplicate admissions at disconnected entrances remain possible. They are preserved as conflicts after exchange, without clock-based winner selection. Local totals are not global attendance before receipt. Signed acknowledgments attest to a particular verified snapshot/context, not future agreement.
- Secure exchange has bounded 900-byte frames, two-operation batches, session/snapshot limits and manual display/scan progression. Large-event throughput, retention/session cleanup and maximum-scale stress are not established. ELQ1 and legacy JSON remain available; old clients need explicit compatible output.
- Enrollment still requires scanning several codes and returning approvals/receipts. Camera scan restart is manual; error wording and technical advanced controls still require facilitation. Novice/screen-reader/user-zoom studies remain unrun. Website role exploration teaches a workflow; it does not provision or authorize a phone.
- No backend, cloud backup, cross-browser database visibility, read-only observer credential, key rotation/recovery system, payment, email delivery, authentication or production ticket cancellation/reissue workflow. These are outside scope.
- Dependency scan: zero runtime advisories at the recorded check; 15 dev/build-tool advisories (13 moderate, 2 low) remain. See STAGE_5A_REPORT.md. No claim of independent penetration/cryptographic review or competition/third-party-license approval.
- Operational entry remains above Vite’s 500 kB chunk warning. The self-hosted explanatory website/screenshots increase offline cache size; measured sizes are recorded in STAGE_5A_REPORT.md. Low-end phone performance remains unmeasured.
- Separate stable HTTPS staging is only prepared locally. No live hostname, project linkage, deployment protection, CDN behavior, certificate or phone install has been verified. Published production is unchanged.
