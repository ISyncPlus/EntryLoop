# Roadmap

## Phase 1 · Completed, owner-confirmed physical reconciliation

The owner reports two physical devices exchanged QR records and displayed identical operations with the expected duplicate admission conflict. Automated regressions remain in place. No new hardware test was performed by Codex during Phase 2A.

## Phase 2A · Current implementation

Local event creation/edit safeguards; CSV/manual attendees; opaque ticket allocation; native signed QR tickets; individual SVG/printable HTML export; public-only event packages; fingerprint pinning; real offline admission; existing QR reconciliation; additive persistence migration; preserved development workbench; automated verification and documentation.

The existing practical organizer/scanner interface is retained. The agency-reference experiment and its animation/dialog/icon packages/media were removed after the user deferred UI/UX work. **Full UI/UX redesign is Stage 4.**

## Phase 2B · Recommendations only, not implemented

1. Authenticate staff devices and bind operation evidence to authorization while preserving deterministic reconciliation. Resolve the unsigned-sync forgery boundary before untrusted/production operation.
2. Design safe organizer-key recovery, key rotation/revocation, ticket cancellation/reissue and offline freshness policy.
3. Validate signed-ticket/provisioning workflows on real phones with all radios off, including restart/install, lighting/distance and realistic entrance throughput.
4. Define privacy/access-control, roster correction/deletion, shared-email handling and retention policies; separate security boundaries from test profiles.
5. Test larger rosters/exports, aggregate quotas, backup/recovery, PWA update ergonomics and operator-friendly batch completeness.

Cloud synchronization, payments, a backend, deployment and unrelated features are outside this authorization. No Phase 2B code has been started. Competition submission requirements/AI and third-party terms still need review before public release.

## Stage 4 · UI/UX

Return to product visual identity and interface refinement when explicitly authorized. The installed design-taste-frontend skill remains the selected design skill. Do not reintroduce the canceled reference, video or animation dependencies without a later request.
