## Event/key mutation inventory

- `events/repository.ts:createEvent`: validates input; generates/signs outside IndexedDB; writes event, non-exportable organizer key and initial policy in one transaction. Failure leaves no partial event/key/policy.
- `updateEvent`: transactional role/revision checks and locked name/date/location; retains event ID/key.
- `issueTickets`: signing outside transaction; atomic issued tokens/catalog/event revision update, duplicate issuance protection. No key replacement.
- `exportEventPackage`: atomically snapshots public metadata/catalog and locks metadata; uses the existing key outside the transaction. No deletion.
- `importEventPackage`: signature/fingerprint/policy checks then atomic public event/catalog/policy update. It rejects replacing an existing organizer-role event or pinned key. Scanner packages never supply organizer keys.
- `security/authority.ts:identity`: returns existing scanner key; creates one only when deliberately enrolling. `changePolicy` requires an existing organizer key and appends signed policy history.
- Event/detail/list/scanner reads and trusted projections were traced. Core domain logic remains untouched.
- No application event deletion, signing-key deletion, database clearing or `deleteDatabase` path was found. The reset path only deletes operations for the two synthetic fixture events after its explicit guard. Test fixtures deliberately delete/alter **only disposable test data** to verify detection/rollback; no production data is involved.
- Workbox cleanup manages asset Cache Storage, not EntryLoop IndexedDB. Dependency code containing database-deletion support is not proof that this application executed it; app databases use declared schemas, not Dexie's missing auto-schema deletion path.

## Local reproduction and acceptance

Before editing, an isolated Chromium context using the unchanged production build created an event in main, added three attendees, issued three tickets, then opened organizer. Organizer displayed the first-event empty screen while main retained all rows and its matching key. Workbench home dropped organizer. This reproduces **loss of access through namespace selection**, not deletion and not the unexplained production history.

After hardening, tests cover successful reads, explicit errors/recovery states, same-profile navigation/restart, both historical migrations, unsupported schemas, key associations, offline reload, two builds/SW update, concurrent edits and record export. Results and environmental limitations are in [RELIABILITY_TEST_RESULTS.md](RELIABILITY_TEST_RESULTS.md).

**Do not resume physical acceptance or call this incident permanently fixed solely because those tests pass.** Locate the original event/authority or establish the loss mechanism, review the production routing change, and perform the MacBook/two-phone verification in [PERSISTENCE_RECOVERY.md](PERSISTENCE_RECOVERY.md).
