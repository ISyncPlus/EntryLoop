# Phase 2B recovery and revocation policy

| Incident                                | Action                                                                                                                                                                                                                                                                              | Limit                                                                                                                                                                                                  |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Lost/compromised scanner                | Organizer: Scanner devices → Revocation and recovery → revoke the identified scanner. Compare full UUID/fingerprint. Distribute updated signed policy or package to every remaining scanner. Enroll a replacement under a fresh identity.                                           | No remote wipe or immediate disconnected revocation. Evidence existing only on the lost device is unavailable until recovered/exchanged.                                                               |
| Scanner still offline with old policy   | Physically carry the current policy QR/JSON or event package to it. Confirm policy epoch and event. Secure sync refuses different policy/catalog contexts. Stop the old device's shift until updated.                                                                               | Equally stale peers can still exchange and admit. There is no trusted online time/freshness oracle.                                                                                                    |
| Revoked scanner's historical admissions | Preserve raw operations/proofs. Current trusted totals exclude all operations by that scanner, including pre-revocation claims. Review them manually against independent records.                                                                                                   | Untrusted timestamps cannot distinguish legitimate past admissions from backdated forgery after key theft. No automatic reinstatement/winner is implemented.                                           |
| Ticket revoked/copied                   | Organizer revokes the opaque issued ticket ID and redistributes policy. Prepared updated devices reject it and exclude its historical admissions while preserving evidence.                                                                                                         | Old signed tickets/packages remain usable on stale devices. Revocation does not invalidate copies immediately offline; cancellation/reissue UX is not part of this phase.                              |
| Organizer browser/device/key lost       | Preserve any surviving scanner logs and public packages. Stop claiming organizer authority. If the original storage/device can be recovered intact, use it; otherwise create a replacement event with a new key and deliberately reprovision/reissue under operational supervision. | No signing-key backup, recovery, rotation or event-key replacement exists. Scanner packages cannot restore organizer authority. Do not recreate an old UUID/key claim or export keys as a workaround.  |
| Browser clearing/eviction               | Avoid private browsing and clearing site data. Keep the same trusted origin, port, browser/profile and install partition. Regularly exchange evidence to another authorized device and return acknowledgments; test reopen before doors open.                                       | Replication improves availability only for successfully exchanged records. It does not back up organizer authority or guarantee OS/browser retention. Storage encryption/durability is not guaranteed. |
| Interrupted exchange                    | Keep both browsers' site data. Resume the stored session, scan its signed offer if needed, request exact missing indices, finish verification and return the signed acknowledgment.                                                                                                 | Partial frames are staged and absent from trusted totals. Acknowledgment not returned means sender delivery remains incomplete. Lost source-only operations cannot be reconstructed from a hash.       |
| Older v1 data/application               | Update app resources normally; close all old app tabs/windows to activate a waiting service worker, without clearing site data. Export v2 packages and enroll scanners.                                                                                                             | Unsigned operations remain historical evidence; never silently sign/promote them. An old app can continue its old behavior until physically updated. Retire old builds operationally.                  |

## Before each event/shift

Confirm the organizer key fingerprint independently. Prepare all issued IDs, latest policy epoch and correct build on each scanner. Enroll deliberately, using entrance aliases and full scanner fingerprints. Verify distinct cryptographic UUIDs, a valid ticket, a local duplicate, a wrong-event ticket, a forged signature, offline reload and actual camera exchange. Record which devices carry the current policy. Keep an organizer device secure and charged; use a managed device with protected access where available.

At shift changes, exchange complete snapshots both ways and return acknowledgments. Compare operation identities/content roots and conflicts. Resolve physical admission disputes through event procedure, not timestamps or count comparisons. Do not erase evidence to make totals match.

## Honest security boundary

Non-exportable CryptoKeys prevent accidental raw export through this application. They do not stop malicious same-origin JavaScript, browser extensions, unlocked-device misuse or OS compromise from invoking signing. No PIN/account access control, hardware-backed attestation, encrypted at-rest roster, secure key backup or independent cryptographic audit is implemented. Those require explicit later engineering scope; insecure private-key export was deliberately not added.
