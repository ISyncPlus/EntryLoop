# Threat model · Phase 2B

## Assets and boundaries

Protect organizer/scanner signing capability, event authority, attendee PII, issued-ticket registry, immutable admission evidence and accurate synchronization status. Inputs from files, QR, clocks and claimed identities are untrusted. Organizer fingerprint comparison is the initial human trust anchor. Device enrollment additionally requires direct comparison of the scanner fingerprint. Profiles do not restrict same-origin code or local users.

## Revocation consequences

Trust is relative to the latest **locally received** root-signed policy. Revoking a scanner/ticket conservatively excludes all related historical admissions but preserves original records/proofs. Claimed times cannot establish a legitimate pre-revocation boundary. Distribute policies to all devices before comparing totals or continuing a shift. Different current policies/catalogs block sync; equal stale ones do not prove organizer freshness.

## Cryptographic scope and recovery

Native ECDSA P-256/SHA-256, strict public-only JWKs and raw r||s signatures. Separate domains cover tickets, packages, enrollment, credentials, policies, admissions and optical sync. Canonical operation roots exclude randomized signature bytes but signatures are verified independently. No custom cryptographic primitive or new crypto dependency was introduced. See PROTOCOL_PHASE_2B.md for exact encodings.

Keys remain non-exportable. There is no safe key backup, recovery, rotation or lost-organizer-authority restoration implemented. Do not export private keys to work around this limitation. See RECOVERY_PHASE_2B.md for lost devices, eviction, stale policy/tickets and interrupted sync procedures.

## Evidence and unverified work

Unit/integration tests exercise authorization, forgery, tampering, collision, revocation, migration, partial transfer and content-root convergence. Chromium/WebKit tests use actual native crypto/IndexedDB/QR pixels and production cached assets, including scanner-key/session persistence through browser-process restart. No mocked scanner callback is physical evidence.

The owner reports Phase 1 physical QR reconciliation with matching logs and the expected conflict. New Phase 2B phone camera, install/permission behavior, lighting/distance, throughput, storage eviction, maximum-scale load, independent cryptographic review and comprehensive accessibility/security audits remain unverified. Stage 4 visual/UX redesign is intentionally deferred.
