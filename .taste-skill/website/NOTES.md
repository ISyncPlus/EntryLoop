# EntryLoop website direction and copy

November 9, 2026. Requested website revision precedes Stage 5A. Existing Stage 4 app remains the operational interface.

## Subject inventory

EntryLoop’s loop is an exchange back to the sender; two independent entrances; signed ticket paper; a phone displaying a code to another camera; light instead of a network; organizer-local keys; independent scanner identities; explicit approval; preserved concurrent admissions; interrupted optical batches; a returned signed receipt; the unchanged local browser workspace.

On this page, **EntryLoop’s signed ticket and optical entrance handoff become an event-poster composition and a two-door story**. Dealt direction: Dressed as something else / borrowed-category, seed 861326675; no redraw. The charcoal/sage sheet was mapped to the existing forest brand and requested primary/secondary/accent roles: forest #164f47, mint #c7eca8, orange #ff743f, cool paper #f6f8f2. Local IBM Plex Sans retained. No invented company/customer imagery or statistics.

## Argument / copy deck

- Doors open. Network off. → explain offline event check-in; actual signed ticket; real organize/prepare destinations.
- The connection is light. → diagram explains sender/receiver verification, independent logs and returned receipt; visibly explanatory, not a simulated admission.
- Find your next move. → interactive organizer/staff journey with actual workflow text and product screenshots; role/step selection changes the content honestly.
- A welcome, not a spreadsheet. → CSV validation, ticket issuance and local record visibility, demonstrated with actual guest-list UI.
- Ready before the rush. → cache, provision, verify fingerprints, approve and rehearse; HTTPS and physical-test limits are explicit.
- Clear about the limits. → browser storage boundaries, concurrent duplicates, stale revocation and unresolved FAILED incident gate.
- Before the doors open. → eight complete answers on network, optical exchange, duplicates, interruption, approval, privacy and lost keys.
- Keep the doors open. → real organizer/staff links and installation/data/help anchors. No fake store downloads, company credits or legal routes.

Full final copy lives in LandingPage.tsx and JourneyExplorer.tsx. No sample business proof, pricing or testimonials. Harbor Makers and its three guests are fictional rehearsal data, labeled in every image caption; replace only when genuine public demonstration material is available. Never substitute real attendee PII into public assets.

## Assets and supplied component

They are project UI, not stock photographs. No external photographs/footage or Unsplash downloads are used: actual working UI is the relevant evidence for offline event software, and avoids network-only assets. Existing local fonts retain OFL attribution. AI assistance and package terms are in THIRD_PARTY_NOTICES.md.

The supplied CinematicFooter/MagneticButton is adapted in src/components/ui/motion-footer.tsx: GSAP ScrollTrigger, aurora/grid, diagonal marquee, wordmark parallax, staggered reveals and magnetic pills. The user explicitly requested these effects; gradient/glass/shadow/hairline/outlined-box/button-fx inspector exceptions apply to the footer only. Source lint comments mark actual exceptions. Normal document flow replaces the example’s fixed full-screen clipped footer to keep narrow/short screens, focus navigation and scrolling usable. No `any`, runtime Google Fonts import, fake app-store links or unrelated Sobers/Volvox copy was retained.

## Structure

Vite React 19, strict TypeScript and Tailwind v4 already existed. components.json now declares shadcn aliases, styles at src/styles.css and @/components/ui → src/components/ui. src/lib/utils.ts supplies cn; Button uses Radix Slot/cva. A new CLI scaffold would replace existing app config unnecessarily, so none was run. GSAP is dynamically loaded with the landing page, not the operational scanner entry. Semantic reading order and content do not depend on animation. Pause motion and prefers-reduced-motion stop travel/continuous effects; magnetic listeners are cleaned up on unmount/media change.
